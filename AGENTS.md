## Project overview

MSDevBuild Eats — a Flutter food delivery app. Flutter 3.x, Dart SDK
`>=3.5.0 <4.0.0`. Runs on web, Android, iOS and tablet from one codebase, and
ships three roles: customer, restaurant partner, delivery rider.

The default backend is a seeded in-memory demo (`DemoDataSource`), so the app
runs with no Firebase project and no API keys. Firebase is the optional second
implementation.

## Setup and verification

```bash
flutter pub get
flutter run -d chrome        # or any connected device
flutter analyze              # must be clean
flutter test                 # must be green
```

## Architecture rules

Clean Architecture with three layers and a strict inward dependency rule. Do
not introduce a different architectural pattern for a new feature, even a
well-known one.

- `lib/domain/` — entities, repository interfaces, use cases. **Pure Dart.** No
  `package:flutter/*`, no Firebase, no `shared_preferences`.
- `lib/data/` — models with JSON mapping, data sources, repository
  implementations of the domain interfaces.
- `lib/features/<feature>/` — presentation only, holding `bloc/` and
  `presentation/widgets/`. Never imports from `lib/data/`.
- `lib/core/` — shared and feature-agnostic: theme, errors, `Result`,
  responsive helpers, storage, reusable widgets.

Verify the first rule at any time:

```bash
grep -rn "package:flutter/" lib/domain/     # expect no matches
```

## State management

BLoC / Cubit (`flutter_bloc`), with `bloc_concurrency` for event transformers.
Not Riverpod, not Provider, not `setState`.

- Cubit when a screen has one action; full Bloc when it has several events.
- Blocs are **not** registered in `get_it`. They resolve their use cases from it
  and are created by `BlocProvider` at the screen that owns them.
- Only `AuthBloc`, `CartBloc` and `ThemeCubit` are hoisted to the app root.
- State classes extend `Equatable` and list every field in `props`.
- Search events use `restartable()` with a 320 ms debounce.

## Error handling

`Result<T>` from every repository and use case — `Success<T>` or
`FailureResult<T>`. Never throw across a repository boundary.

Data sources throw `AppException`. Repositories translate to a domain `Failure`
through `mapErrorToFailure` (`lib/core/utils/error_mapper.dart`), in exactly one
place. The UI renders `failure.message`, never a raw exception.

## Business rules (hard constraints)

- Order totals are recomputed from the `Cart` entity when the order is created.
  Never trust a total posted from the checkout screen.
- `PlaceOrder` creates the order **and** clears the cart. An order that exists
  with a stale basket behind it is a real bug class.
- `OrderStatus` owns its own state machine (`next`, `isTerminal`,
  `trackingStages`). The partner's advance button, the customer timeline and
  the rider job card all read from that one definition — do not duplicate it.
- Adding a dish from a second restaurant emits a `pendingConflict` state. Never
  silently replace the basket.
- Fee constants live in `PricingPolicy` next to `Cart`. Do not inline them.
- `Promo.discountFor(subtotal)` applies percentage, cap and minimum spend. All
  promo maths goes through it.

## Testing

`flutter_test` + `bloc_test` + `mocktail`, under `test/`, mirroring the layers
(`test/domain`, `test/data`, `test/bloc`, `test/widget`).

Every bloc ships with a `bloc_test` covering loading, data and failure, using a
mocked use case. No emulator, no network.

## Conventions

- Entities are immutable, `Equatable`, with `copyWith`, and carry their own rules.
- Orchestration lives in use cases, not in blocs. A bloc asks for one thing.
- The backend is swapped at the repository interface via `AppConfig.backend`.
  Screens never change when it flips.
- Lints are enforced (`analysis_options.yaml`): single quotes, `const`
  constructors, declared return types, `final` locals, no `print`.

## Off-limits

- `lib/firebase_options.dart` — generated by `flutterfire configure`.
- `build/`, `.dart_tool/`, any `*.g.dart` or `*.freezed.dart`.
- Do not add a package to `pubspec.yaml` without asking first.
- Demo seed data belongs only in `lib/data/datasources/local/seed/`.
